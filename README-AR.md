# لوحة إدارة ATHNTA × LAVINTA

هذه الحزمة كاملة ومبنية على نسخة GitHub ذات المعرف 5bf58acf033c7faebfeed4b41d8f96c5af57b9c7. لم تُنشر تلقائيًا ولم تتغير بيانات Firebase. واجهة المعرض والثيمات محفوظة كما كانت.

## الجديد

- واجهة إدارة متجاوبة بقائمة تنقل وملخص مستقل للمتجرين.
- أعداد المنتجات والتصنيفات والتقييمات والصور من Firestore مع تحديث مباشر.
- مقارنة المتجرين، آخر الإضافات، توزيع المنتجات، وكشف المنتجات بلا صور أو المرتبطة بتصنيف مفقود.
- البحث في المنتجات مع الاحتفاظ بالإضافة والتعديل والرفع والثيمات.
- تقارير Google Analytics لآخر 7 أو 30 أو 90 يومًا: المستخدمون، دخول كل متجر، ضغطات واتساب، مصادر الزيارات والمنتجات الأكثر مشاهدة، والنشطون خلال 30 دقيقة.
- تصدير تقارير الزيارات والمنتجات بصيغة CSV، وطباعة التقارير.

## التركيب

احتفظ بنسخة من مشروعك الحالي. انسخ محتويات هذا المجلد إلى جذر المشروع، حيث index.html وpackage.json، مع استبدال الملفات المطابقة. انشر أولًا على نسخة Preview في Vercel ثم اختبر الدخول والرفع قبل اعتمادها. النسخة التجريبية تستخدم قاعدة البيانات نفسها ما لم تخصص لها مشروع Firebase منفصلًا.

احتفظ بجميع متغيرات البيئة الحالية: ADMIN_UIDS وFIREBASE_ADMIN_PROJECT_ID وFIREBASE_ADMIN_CLIENT_EMAIL وFIREBASE_ADMIN_PRIVATE_KEY وIMGBB_API_KEY. لا تضع قيمها في الملفات. لا تحتاج إلى تغيير قواعد Firestore الحالية لهذه اللوحة.

Node.js محدد بإصدار 22.x. للتطوير المحلي استخدم npm ci ثم npm test ثم vercel dev مع إعداد البيئة. Live Server لا يشغل وظائف API اللازمة للدخول والرفع والتقارير.

## تفعيل الزيارات داخل لوحة الإدارة

معرّف G-YJ9G35FSL3 يسجل الزيارات، لكنه لا يمنح لوحة الإدارة إذن قراءتها. نفذ الخطوات التالية مرة واحدة:

1. افتح مشروع Google Cloud الذي ينتمي إليه حساب الخدمة الحالي، وفعّل Google Analytics Data API من مكتبة APIs.
2. في Google Analytics افتح الإدارة ثم إدارة الوصول إلى الموقع (Property access management)، وأضف البريد الموجود في FIREBASE_ADMIN_CLIENT_EMAIL بدور Viewer (مشاهد).
3. من تفاصيل الموقع (Property details) انسخ Property ID الرقمي. هذا ليس معرّف مصدر البيانات Stream ID، وليس معرّف القياس الذي يبدأ بـ G-.
4. في Vercel أضف متغير GA4_PROPERTY_ID بقيمة ذلك الرقم إلى بيئة النشر المطلوبة ثم أعد النشر.
5. افتح تبويب التقارير واضغط تحديث. تظهر رسالة توضيحية إذا كان الربط غير مكتمل؛ باقي لوحة الإدارة يعمل بصورة مستقلة.

لا ترسل المفتاح الخاص أو تضفه إلى GitHub. الخادم يستخدم حساب الخدمة الحالي ونطاق قراءة Analytics فقط، ويتحقق من صلاحية المدير قبل كل طلب.

مرجع الربط الرسمي: https://developers.google.com/analytics/devguides/reporting/data/v1/quickstart

## معنى التحديث والتقارير

بيانات المحتوى تأتي عبر اشتراكات Firestore مباشرة، وتتوقف عند إخفاء الصفحة أو الانتقال إلى إدارة المحتوى لتقليل القراءات. قد تظهر نسخة مخزنة عند انقطاع الاتصال ويُوضح ذلك في حالة الاتصال. هذه القراءات تخضع لاستهلاك مشروع Firebase.

تقارير Analytics تُطلب كل دقيقة أثناء فتح التبويب إذا فعلت الخيار، وتُخزن مؤقتًا على الخادم لمدة دقيقة. زمن وصول البيانات إلى Google مستقل عن ذلك؛ التقارير المعتادة ليست لحظية، والنشطون محسوبون خلال آخر 30 دقيقة للموقع كله. مصادر الزيارات أيضًا للموقع كله. فلتر المعرض يخصص أحداث الدخول وواتساب ومشاهدات المنتجات.

مرات الدخول قد تزيد على عدد المستخدمين. ضغط واتساب مؤشر اهتمام وليس طلبًا مكتملًا أو إيرادًا. لا توجد قاعدة طلبات أو مبيعات، لذلك لا تُعرض أرقام مالية افتراضية. الأيام التي تظهر في الرسم هي الأيام التي سجلت دخولًا.

تقرير المحتوى يعرض الموجود الآن، والإضافات خلال الفترة بحسب timestamp؛ العناصر بلا تاريخ تظهر منفصلة. لا يمكن استرجاع أعداد المنتجات المحذوفة تاريخيًا من هذا التقرير. تصدير المنتجات يشمل المخزون الحالي ضمن فلتر المعرض، وليس الإضافات فقط.

## تنظيم المجلد

- api: وظائف الخادم المحمية للدخول والرفع والثيم والتقارير.
- lib: التحقق من الصلاحيات وقراءة Analytics وأدوات الخادم.
- js وcss: سلوك وتنسيق الواجهة والإدارة والثيمات.
- assets: ملفات الصور والأصول المستخدمة.
- tests: اختبارات الصلاحيات والواجهة والثيم والتقارير. ليست مطلوبة لتشغيل الموقع، لكنها مفيدة للصيانة ومستبعدة من النشر.
- package-lock.json: تثبيت الإصدارات المتوافقة؛ احتفظ به لتجنب اختلاف الاعتماديات.

حُذفت من هذه الحزمة ملاحظات الإصلاحات القديمة المكررة وقالب القواعد غير المخصص؛ لم تُحذف ملفات تشغيل أو أصول مستخدمة. لا تشمل الحزمة node_modules أو ملفات Git أو أسرار البيئة.

## التحقق

اختبارات آلية محلية تشمل التحديث المباشر، تجاهل الاستجابات القديمة، حماية التقارير وصلاحيات الإدارة، العرض الآمن، والتوافق مع وظائف المعرض والثيم الحالية. لم يُختبر حساب Analytics الفعلي لعدم توفر Property ID وصلاحيته، ولم تُنفذ عمليات كتابة على بياناتك أثناء الإعداد. بعد النشر اختبر الدخول والرفع وربط Google من حسابك.
